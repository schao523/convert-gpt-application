# Deterministic operations
Use one JSON object on stdin to the registered steam-contract-checks capability. Its operation is inventory, conversion, activity, production, evidence, usage or framework. Read its input/output contract first. No user-supplied program is executed. Every output includes status, checks and limitations.

Inventory takes members with path and sha256 plus optional source/target mappings. Conversion takes source_evidence_available, source_counts/target_counts for headings/tables/images/citations and unresolved_exceptions; lack of source evidence is NOT VERIFIED. Activity takes age_or_grade, time, materials, focus or focus_clear, adult_review, safety_review, unsafe_hazards, steam_domains, 13 sections, measurement, redesign, mode, game_switch_confirmed and state A6/A7. Production takes approved_design, medium, learning_objective, rules, states/action guards, actions, end_conditions, assets, accessibility, inputs_outputs, tests, version, three levels, produced, entrypoint, artifact_text and artifact_sha256. Evidence takes produced/executed/tested with respective evidence fields and optional learning observations. Usage takes rows with material_id, trigger, section, provenance, rights_decision, read_state and distributed. Framework takes markdown, comparison_text and authority=markdown.

These are bounded structural record checks. PASS never certifies semantic fidelity, physical safety, actual source reading, actual browser execution or learning gain. Preserve each limitation in the result returned to the requesting Skill. Missing originals remain unavailable; supplied historical audits are not a new independent verification. No broad filesystem scans, network, secrets, code evaluation or persistent child records are needed.
