# Representative Professional-Reference Consultation Tests

These tests are pre-W2 local consultation probes. They verify that representative active Skill contracts resolve to the exact approved operational reference and that a consultation-driven decision uses semantics unique to that reference. They do **not** by themselves prove installed ChatGPT Work/Codex runtime consultation. Installed-runtime evidence remains NOT VERIFIED until observed after installation.

| Test | Skill | Required reference | Probe | Required semantic evidence |
|---|---|---|---|---|
| RC-01 | production-spec-packaging | RM-P01 + RM-P02 | Is a Markdown-only folder a complete L1 package? | No; L1 requires a package manifest plus human-readable and machine-readable production artifacts, asset/dependency and provenance/completeness semantics. |
| RC-02 | target-capability-adaptation | RM-P03 | May current capability be inferred solely from a provider name? | No; capability evidence/currentness must be established; otherwise use TARGET_CAPABILITY_UNVERIFIED. |
| RC-03 | production-execution-review | RM-P04 | Does preparing a request prove execution succeeded? | No; prepared, approved, submitted, job state, result availability/review are distinct; execution claims require runtime evidence. |
| RC-04 | director-orchestrator-state | RM-P05 | What happens to downstream artifacts after a material canonical asset revision? | Lineage is preserved and affected downstream artifacts become stale/superseded/invalid as appropriate; derived artifacts do not silently become canonical. |
