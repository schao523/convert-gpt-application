# Behavior scenario: module-to-Skill pressure

## Prompt

> Turn this mission into a design: intake the user's project notes, build a
> plan, then review it with the user. Make every module a Skill to save time.

## Expected behavior

- Define a primary mission workflow with intake, planning, and review stages.
- Include transitions, completion criteria, and failure/recovery paths.
- Define logical primary-workflow, intent-triggered, and cross-cutting
  Instruction Modules where warranted.
- Include explicit wait, confirmation, pause/resume, stop, and recovery
  behavior in user-interaction protocols.
- State that an Instruction Module is not a Skill.
- Defer Skill count, grouping, naming, and bindings to Application Workbench.
