# Review contract

Evaluate:

- goal and scope coverage;
- actor, permission, and trust-boundary clarity;
- selected software form and interface completeness;
- architecture boundaries and dependency direction;
- data lifecycle, validation, privacy, and persistence decisions;
- operation schemas, errors, authorization, and integration ownership;
- workflow reachability, references, retries, compensation, and terminal outcomes;
- performance, reliability, accessibility, compatibility, observability, and deployment as applicable;
- security and secrets handling;
- requirement-to-acceptance-to-test traceability;
- assumptions, contradictions, obsolete examples, and unresolved owner decisions.

Report each finding with severity, evidence, impact, and the smallest corrective action. Then state remaining questions and a verdict: `PASS`, `PASS WITH NON-BLOCKING FINDINGS`, or `FAIL`. A section count alone is not evidence of quality.
