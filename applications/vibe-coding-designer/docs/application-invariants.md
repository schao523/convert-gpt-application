# Application invariants

- Choose the simplest software form satisfying the user's goals; use a Web GUI only when explicitly requested or clearly required.
- Preserve the explicit eleven-stage guided intake and ask one focused question at a time.
- Produce non-executable design artifacts, not the designed application.
- Use the fourteen-section software specification contract with justified `Not applicable` decisions.
- Keep Web-specific UI, Tailwind, WCAG browser, responsive, and SEO guidance conditional.
- Treat persistence, PostgreSQL, Node.js, and backend frameworks as optional choices derived from requirements.
- Preserve exact workflow state and binding identifiers and validate their references deterministically.
- Never invent test coverage or verification evidence.
- Never include credentials, private paths, or local-only conversion data in distributions.
- Use one portable skill tree for Codex and OpenClaw.
