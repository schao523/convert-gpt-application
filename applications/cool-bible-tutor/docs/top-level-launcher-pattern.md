# 頂層設定啟動器模式

「明明可知 Obvious One」插件可用一個位於插件根目錄 `scripts/` 的穩定 CLI，包住較深層的專用工具。使用者只學一個入口；各技能仍保有單一職責、可獨立測試的底層腳本。

## 邊界

- 啟動器負責參數解析、插件根目錄定位、私人資料目錄選擇、前置檢查、指令委派與退出碼傳遞。
- 專用工具負責實際建置、驗證、核對、檢索或外部整合。
- 啟動器不複製領域邏輯、不擴張權限，也不把生成資料寫入插件。安裝與下載只能由明確子指令觸發；例如 `setup-rag --accept-downloads` 在顯示範圍並取得同意後，才呼叫內附 bootstrap。
- `--data-dir` 優先於插件專用環境變數；宿主提供 `PLUGIN_DATA` 時可作為下一層；最後才使用作業系統的個人應用資料目錄。
- 診斷中，必要依賴缺失應回傳非零；選用整合未設定應清楚標成 optional，而不是破壞核心功能。

## 建議指令形狀

每個插件只實作實際需要的子指令，常見名稱為 `doctor`、`init`、`status`、`verify`、`review` 與整合專用命令。長時間或具副作用的工作保持明確命令，不在安裝、啟用或工作階段啟動時偷偷執行。

## 測試契約

先以失敗測試固定：資料目錄優先級、禁止寫入插件、底層命令與參數映射、退出碼傳遞、必要與選用依賴的差異、狀態報告，以及外部整合失敗時的安全降級。測試替換的邊界應是外部程序啟動，不應仿造領域工具內部行為。

通用的路徑、內容定址快取、下載驗證、安全解壓縮、交易式啟用與 adapter identity 契約由 build-time framework 提供，並把小型 bootstrap 複製到每個成品的 `vendor/obvious-one-runtime`。使用者不需另裝 framework plugin。執行依賴可依 digest 共用；領域內容一律留在各插件自己的 `ObviousOne/plugins/<plugin-id>` 目錄。
