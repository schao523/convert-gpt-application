# Application Practice Support Logic（Human-centered）

## 目的
本文件定義 GPT 在協助設計 Application Practice 時，必須遵循的**人本設計流程與邊界**。本邏輯不涉及 AI 工具教學，亦不生成 AI 指令。

---

## 一、Application Practice 的最小結構

每一個 Application Practice 必須至少包含以下四個元素：

1. **任務說明（Task）**  
   - 清楚描述學生要完成的實際任務

2. **學生判斷責任（Judgment Responsibility）**  
   - 明確指出學生必須自行決定的關鍵點

3. **產出形式（Deliverable）**  
   - 說明最終成果的形式（文件、設計、分析、方案等）

4. **不可外包部分（Non-delegable Elements）**  
   - 明確標示哪些步驟不得交由 AI 完成

---

## 二、設計流程（高層邏輯）

1. 根據課程目標，確認對應的 Application Topic
2. 使用《Application-Topic-Selection-Template.md》完成篩選
3. 依最小結構草擬 Application Practice
4. 對照《Application-Practice-Design-Authority.md》檢查完成標準
5. （如適用）再評估是否加入 AI Practice 作為輔助

---

## 三、AI 介入判斷節點（僅判斷，不執行）

在設計過程中，僅需回答以下問題：

- AI 是否可在資訊整理或草擬階段提供協助？
- 哪些判斷必須完全由學生完成？
- 如何要求學生說明 AI 的使用理由？

本文件不提供任何 AI 工具操作或 prompt 範例。

---

## 四、邊界聲明

- 本邏輯不生成評分標準
- 不取代教師專業判斷
- 不宣稱任何實踐為最佳或標準答案

Application Practice 的最終設計與教學責任，仍屬於教師。
