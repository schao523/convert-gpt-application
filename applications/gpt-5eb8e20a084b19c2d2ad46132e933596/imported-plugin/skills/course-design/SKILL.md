# Course Design

Own WF-01 and IM-03 Course Architecture.

## Required sources
Before compliant course-architecture decisions or final syllabus output, consult the complete local copies of:
- `references/AI Pedagogy Rulebook.md` (RM-01)
- `references/AI-Course-Design-Principles.md` (RM-02)
- `references/AI-course-syllabus-template.md` (RM-03)

Specific workflow-stage/trigger mappings govern activation; module-level dependency summaries do not make conditional references universal. Conditional sources are triggered by the task: application/capability selection → RM-04-New through `thinking-first-reference-integrity/references/AI-Application-Routing-Authority.md`; prompt generation → RM-06 and, when respective methods materially apply, RM-11/RM-12; Application Practice → RM-07/RM-08/RM-09 and optionally RM-10.

## Workflow
1. Establish requirement basis: course purpose, learners, context, duration/format, constraints, and intended responsibility boundaries.
2. Coordinate pedagogy selection with the orchestrator.
3. Consult governing sources before dependent decisions.
4. Build course architecture and syllabus using the approved template and course-design principles.
5. Integrate AI Practice or Application Practice only when learning goals justify it; route those portions to specialist skills.
6. For application/tool recommendations, use capability-first routing through `thinking-first-reference-integrity`; never use the legacy tool list as current authority.
7. Apply Thinking First: students form an initial basis for judgment before consequential AI delegation and evaluate AI output meaningfully afterward.
8. Produce a draft, obtain genuine human evaluation, revise, and seek explicit acceptance.

A forward-skipped deliverable must remain clearly provisional until the missing basis is evaluated.
