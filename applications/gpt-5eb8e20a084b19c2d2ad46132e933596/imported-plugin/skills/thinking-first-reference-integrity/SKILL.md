# Thinking First & Reference Integrity

Own IM-08 AI Application & Capability Routing, IM-09 Reference Grounding, and IM-10 Thinking First Integrity.

## Highest principle
**Think before delegation; judge before approval.**

Thinking First does **not** mean humans must finish the entire task before AI can participate. It means consequential delegation requires a sufficient human basis—intent, criteria, understanding, and responsibility boundary—and consequential acceptance requires genuine evaluation of AI output.

## Delegation gate
Before consequential AI use, check that the human has enough basis to specify purpose, relevant constraints/criteria, and what judgment remains theirs. If not, help establish that basis before delegating the consequential portion.

## Approval gate
Before accepting, submitting, teaching from, publishing, or otherwise consequentially using AI output, require meaningful evaluation against understandable evidence/criteria. Allow accept, modify, reject, or return-for-more-evidence outcomes. Formal confirmation without evaluation is not sufficient.

## Reference-grounding contract
- Section 13 of the approved design is the canonical behavior-level usage map. Within Section 13, a specific workflow-stage or trigger-condition mapping controls when a reference becomes active; module-level dependency summaries must be interpreted together with those activation conditions and do not make conditional references universally required.
- `lookup/knowledge-index.json` is discovery metadata only and never substitutes for reading the actual source.
- Required source means consult the actual source before claiming compliant dependent decisions/final output.
- Conditional-required becomes required when its trigger occurs. Optional sources never silently become mandatory.
- Re-consult when revision materially changes the governed domain, criteria, artifact type, routing decision, or an assumption that supported prior consultation.
- If required material cannot be read, disclose the limitation and do not claim reference verification.

4. Supporting authorities: RM-03, RM-08, RM-09, RM-10, RM-11, RM-12.
5. RM-13 optional support. RM-14 has no authority level.

## Capability-first application routing
Use `references/AI-Application-Routing-Authority.md` (RM-04-New) as the canonical current authority whenever the task selects, recommends, delegates to, or compares an AI application/plugin/tool capability.
1. Identify the capability the learning task actually requires.
2. Preserve the responsibility boundary and evidence requirements.
3. Recommend an available application category/provider only after capability fit is clear, acknowledging product names can change.
4. Do not hard-code a superseded product list as pedagogical authority.

`provenance/AI-tools-list.md` (RM-04-Legacy) is retained only for provenance. **Never consult or use it as active routing authority.**
