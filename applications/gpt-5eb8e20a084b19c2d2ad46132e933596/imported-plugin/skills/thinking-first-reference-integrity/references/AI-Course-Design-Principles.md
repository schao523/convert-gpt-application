

**AI-Course-Design-Principles.md**

**（Prompt-aware｜課程設計專用）**

**資源定位說明**  
本文件用於指導 **AI** **課程設計（AICourse Design****），  特別適合在「使用者實際應用情境中（如神學、教育、教會事工）」教授 Prompt Engineering。

⚠️ 本原則**不適用於** **AI practice** **即時生成或教學 prompt** **的行為控制**，  
亦不取代 Pedagogy Guardrails 或 TeachingPrompt Design Checklist。

* * *

**🎯** **核心目標**

* 讓 Prompt Engineering 成為 **可被教、可被學、可被評估** 的課程能力
* 避免將 Prompt Engineering 教成抽象技巧或去情境化工具課
* 確保 AI 課程設計以「人類判斷與責任」為中心

* * *

1️. **情境先於技巧原則**

**Context Before Technique**

Prompt Engineering 必須嵌入具體應用情境中被教授，而非作為抽象技巧獨立教學。

課程設計時，必須先明確：

* 使用者角色（如牧者、教師、學生）
* 實際任務情境（如釋經、教材設計、課程規劃）
* 任務中的責任與限制

Prompt Engineering 是情境化能力，而非語法技巧。

* * *

**2️. 任務導向而非工具導向原則**

**Task-Driven, Not Tool-Driven**

AI 課程的學習單位應以「任務」為核心，而非以工具或功能為核心。

* 課程學習成果不應是「學會某種 prompt 技巧」
* 而是「能在特定任務中做出合適的 prompt 判斷」

Prompt 是完成任務的中介能力，不是課程終點。

* * *

**3️. Prompt** **作為責任表達原則**

**Prompt as Responsibility Expression**

在 AI 課程中，Prompt 應被視為：

對任務理解、角色責任與判斷界線的外顯表達。

課程設計應引導學生說明：

* 為何這樣設計 prompt？
* 這個 prompt 限制了 AI 什麼？
* 哪些判斷仍然必須由人類承擔？

* * *

**4️. 人類判斷先行原則**

**Human Judgment Before AI**

Prompt Engineering 的教學，必須建立在人類已先完成關鍵判斷的前提下。

課程設計應確保：

* 在設計 prompt 前，學生已理解任務目的
* 已做出初步判斷並意識到風險與限制

Prompt 不是用來「想清楚問題」，  
而是用來執行「已想清楚的判斷」。

* * *

**5️. 漸進顯性化原則**

**Progressive Externalization**

Prompt Engineering 能力的培養，應採取漸進方式：

* 初期允許直覺與嘗試

* 後期逐步要求學生：

* 解釋設計理由

* 比較不同 prompt 的後果

* 修正 prompt 以反映更成熟的判斷

* * *

6️.**可評量性原則**

**Prompt Must Be Assessable**

課程中使用的 prompt 必須是可被討論、比較與改進的。

課程設計應建立評量面向，例如：

* 是否清楚定義任務範圍
* 是否避免過度外包給 AI
* 是否保留人類最終判斷權

Prompt Engineering 是一種可評量的能力，而非主觀感覺。

* * *

**7️. 避免去情境化原則**

**Avoid Decontextualized Prompt Teaching**

課程應避免：

* 大量「萬用 prompt 模板」
* 與應用情境脫鉤的 prompt 技巧教學

若提供範例 prompt，必須清楚標註：

* 適用情境
* 使用限制
* 不適用場合

* * *

**8️.  Prompt** **作為反思對象原則**

**Prompt as Object of Reflection**

在 AI 課程中，prompt 本身應成為反思對象。

課程設計應包含：

* prompt 設計後的反思活動
* 對 prompt 責任界線的檢視與修正

* * *

**🧠** **原則總結**

**Prompt Engineering** **在 AI** **課程中，  
不是被單獨「教會」，  
而是被放進真實任務中，  
讓學生學會負責任地使用。**
